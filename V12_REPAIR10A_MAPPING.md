## Cross-cutting observations

- Authenticated stores are namespaced by `user:<id>:` through `getScopedStorage`; guest stores keep the existing V4–V11 keys. Hydration must target the authenticated namespace only.
- `AccountResetGate` waits until NextAuth session status is no longer `loading` before mounting the store-provider tree. That protects initial namespace capture but does not refresh already-mounted stores after a pull.
- Existing providers persist and derive the UI from the domain stores above. The current hydrate function writes several unrelated legacy-shaped keys directly and emits no notification, so mounted providers remain stale.
- Current guest migration detection in `/me/account` reads guessed legacy JSON fields (`study.profile.totalXp`, `vocabulary.states` as an array, `review.items` as an array, and `daily-plan.completedDates`) instead of calling the V4–V11 storage readers.
- The Review Prisma row currently stores only a lossy summary. Its mapper needs a domain snapshot path so the local ReviewStore schema, mastery history, counts, timestamps, and metadata survive round trips.
